> أخبرنا عن أسرتك وميزانيتك، ونرتّب لك بقالتك بأذكى توزيع — **الأنسب لك تحديداً**، لا الأرخص ولا الأغلى.

تطبيق ويب عربي (RTL أولاً) مفتوح المصدر لإدارة ميزانية البقالة في البحرين، مبني على قاعدة بيانات مفتوحة تضم **39,831 منتجاً من 37 متجراً إلكترونياً بحرينياً** (لقطة 2026-10-25)، مع محرك توصية حتمي قابل للتفسير بالكامل: لكل بند في خطتك سبب مكتوب وأرقام واضحة، والمتاجر مجرد **مراجع أسعار** يعتمد فيها المحرك على **الوسيط**.

## أبرز الميزات

- **معالج بدء ذكي** (8 خطوات + بدء سريع + إدخال باللغة الطبيعية العربية) — أقل من دقيقتين، مع مقترح ميزانية ذكي وسلّم مستويات بحريني.
- **صفحة الخيارات المتقدمة**: أكثر من **500 رافعة** تحكم دقيقة — تعديل كميات 55 احتياجاً، 34 قيداً غذائياً/صحياً، مستويات جودة لـ 43 تصنيفاً، أوزان المحرك الخمسة، توزيع الميزانية على 8 مجموعات، 10 ضوابط نمط حياة، تفضيلات 37 متجراً و366 علامة. الأساسيات تكفي الغالبية، والمتقدمة لمن أراد الضبط الدقيق.
- **محرك التوصية «النقطة المثلى»**: يقدّر احتياج أسرتك (أعمار، رضّع، عادات)، يحاكي العبوات والهدر (الأسرة الكبيرة ← عبوات عائلية؛ الفرد ← أحجام تنتهي قبل انتهاء صلاحيتها)، ثم يخصص تحت الميزانية بسلّم تقليص شفاف يُبقي بنود الرضّع محفوظة.
- **5 أنماط خطط** (طوارئ −32% / اقتصاد −18% / توازن / راحة +15% / مخصص) بإزاحات مئوية صريحة ومقارنة حية، ووضع **ماذا لو؟**.
- **شرح مفهوم لكل بند**: «لماذا هذا المنتج؟» بتركيبة تقييم بالنسب المئوية + 3 بدائل (أوفر/مكافئ/أفضل) بتبديل فوري، ولوحة **شفافية بالأرقام** (مستهدف/محقق لكل مجموعة، الاحتياطي، حصة الترفيه، جولات التحسين، اقتصاد السعرات).
- **العناصر العامة وأظرف الميزانية**: اختر «شوكولاتة» بلا علامة وحدد نطاقاً (مثل 1.500–7.000 د.ب) ويتولى المحرك تشكيلة متنوعة مناسبة.
- **قائمة تسوق** حسب المتجر مع تسجيل الأسعار الفعلية، **مخزون منزلي** يُخصم من الطلب، **تتبع إنفاق**، **تنبيهات أسعار**.
- **مركز تقارير** قابل للطباعة: 8 أنواع، A4/A5/Letter/80mm، وضع توفير الحبر، أسماء مخصصة (الأسرة/المعدّ/الخطة)، نسخة عامة أو تفصيلية، تصدير CSV/JSON ومشاركة.
- **حاسبات ذكية**: حفاضات، حليب أطفال، تدخين (18+، محايد بلا وعظ)، كم يكفي؟، سعر الوحدة، الضيافة، تقسيم المصروف.
- **مؤشر أسعار وسلال قياسية**: أي متجر أرخص لسلة أسرة/رضيع/طالب هذا الأسبوع؟
- **مجتمع**: مشاركة الخطط، مساهمات (تصحيح أسماء/أسعار/منتجات جديدة) بتصويت ومراجعة.
- **لوحة إدارة كاملة**: CRUD منتجات مع تراكبات تحفظ التعديلات اليدوية، مركز استيراد (dry-run ثم تطبيق) لأرشيفات Markdown/JSON، سجل تدقيق مع تراجع انتقائي، طابور مراجعة.
- **حركة سلسة**: طبقة حركة مشتركة (تلاشي، تعاقب، عدّادات، أشرطة، حلقات) تحترم تفضيل تقليل الحركة من التطبيق ومن نظام التشغيل.
- **خصوصية أولاً**: يعمل بلا حساب؛ بيانات أسرتك في جهازك (localStorage)؛ لا تتبع.

## التشغيل السريع

المتطلبات: [Bun](https://bun.sh) (يعمل مع npm/pnpm أيضاً بخطوات مكافئة).

```bash
git clone https://github.com/hasan-sdaif/khassis-baqalatak.git
cd khassis-baqalatak
bun install
cp .env.example .env     # مسار قاعدة بيانات SQLite
bun run db:push          # إنشاء قاعدة البيانات
bun run dev              # التطبيق على http://localhost:3000
```

ملاحظة: الكتالوج الكامل يعمل مباشرة من `data/curated/catalog.json`؛ قاعدة SQLite للإضافات المجتمعية والخطط المشتركة وتراكبات الإدارة. قبل النشر العام، اضبط `ADMIN_API_KEY` بمفتاح عشوائي طويل في بيئة الخادم. هذا المفتاح المشترك حماية أولية فقط وليس نظام صلاحيات متكاملاً. راجع `docs/KNOWN_LIMITATIONS.md` و`docs/CONTINUATION_FINDINGS.md` لمعرفة ما تم التحقق منه وما بقي.

## حالة التحقق الحالية

راجع `PROGRESS.md` و`docs/CONTINUATION_FINDINGS.md` لمعرفة ما اختُبر فعلياً وما بقي غير متحقق. الفحوص: `bun run test` (37 اختبار محرك/خصائص/أمثلية)، `node scripts/test-classification.cjs` (تصنيف)، `node scripts/test-api.cjs` (API، يتطلب خادماً حياً)، `bun run typecheck`، `bun run lint`، `bun run benchmark`، `bun run data:audit`، `bun run check:openapi`. لا تعتبر المشروع جاهزاً للإنتاج قبل نجاح التثبيت والبناء وفحوص النوع والـ lint واختبارات API وE2E في بيئة الاعتمادات الكاملة.

لاستكمال العمل على المشروع، ابدأ من `PROGRESS.md` و`docs/CONTINUATION_FINDINGS.md` و`docs/FINAL_REPORT.md` ثم نفّذ الفحوص بنفسك، ولا تتجاوز قيود البيانات والأمان الموثقة في `DATA_LICENSE.md` و`docs/KNOWN_LIMITATIONS.md`.

## مبادئ الخوارزمية

1. **تقدير الطلب**: قواعد استهلاك موثقة لكل فئة عمرية + وحدات عادات (رضّع/تبغ/قهوة…) + مواسم (رمضان…) − المخزون المنزلي.
2. **ملاءمة العبوة**: محاكاة هدر الصلاحية بعد الفتح والمغلق، والشراء الأسبوعي للتلف سريع الانتهاء. `سعر الوحدة الفعّال = الكلفة / الكمية القابلة للاستهلاك`.
3. **النقطة المثلى**: رتبة مئيلية مستهدفة `π*` تتحرك مع مؤشر سعة الميزانية `T` — دالة غاوسية تكافئ القرب وتعاقب الطرفين.
4. **التخصيص**: جشع ترقيات بحد أدنى للعائد الحدي (لا إنفاق لمجرد الإنفاق) + سقف للتحلية + سلّم تقليص شفاف عند العجز (الرضّع أولاً بالحفظ) + تحسين محلي (تبديلات ذكية ≤ 3 جولات).
5. **الشرح والبدائل**: أكواد أسباب رقمية تُترجم لجمل عربية دقيقة، وثلاث بدائل لكل بند.

كل المبالغ بالفلس (أعداد صحيحة). النتائج حتمية (نفس المدخلات ← نفس الخطة). المرجع التقني الكامل في `docs/ALGORITHM.md`.

## البيانات المفتوحة

- `data/curated/catalog.json` — الكتالوج الكامل (39,831 منتجاً، أحجام محللة، احتياجات، وسوم، أسعار 37 متجراً + الوسيط).
- `data/raw/grocery-db-bahrain/` — أرشيف Markdown الأصلي؛ أعِد استيراده من **مركز الاستيراد** في لوحة الإدارة (dry-run ثم apply) أو الصق أي أرشيف بنفس الصيغة.
- `GET /api/dump` — تنزيل الكتالوج JSON مباشرة.
- المصدر: متاجر إلكترونية بحرينية عامة؛ **الأسعار مؤشرات تاريخية تقريبية** وليست عروضاً تجارية — تحقق قبل الشراء.
