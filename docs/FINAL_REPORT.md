# تقرير التسليم والمراجعة — خصص بقالتك

**تاريخ التقرير:** 26 أكتوبر 2026 (بعد جولة التطوير 4)
**نطاق الجولات 2-4:** إصلاحات محرك التخطيط وترابط البيانات، إدارة المنتجات، حدود API، مشاركة الخطط، التقارير، ثم التحقق الكامل في بيئة اعتمادات مكتملة وإصلاح خلل الأقفال.
**حالة المنتج:** نسخة عمل محسّنة ومتحقق منها آلياً؛ بناء الإنتاج وDocker/CI لم يُثبتا بعد.

## النتائج المنفذة (الجولات 2-3)

- توحيد تمثيل جميع عناصر الخطة عبر `getAllPlanItems()` مع إزالة التكرار، وتطبيقه في ملخصات الخطة والتقارير والمخزون والإنفاق والمجتمع.
- إصلاح ميزانيات الأظرف بحيث تحترم المنتجات المختارة الحد المالي الفعلي، ويطابق إنفاق الظرف مجموع سطور المنتجات.
- تحسين مشاركة الخطط: نقل إعداد التوصيل والتفضيلات الضرورية، وإزالة أسماء/معرّفات الأسرة من المسار المجهول، وطلب الموافقة قبل النشر العام.
- تقوية نقاط تعديل الكتالوج: تحقق من الفئة والمتجر، تحديث الحقول المشتقة (الاسم المطبع، الاحتياج، الوسوم، السعر الوسطي، سعر الوحدة، التوفر)، وحفظ التغيير وسجل التدقيق ضمن معاملة حيث طُبّق.
- تطبيق حدود قراءة JSON على عدة مسارات، وإضافة اختبارات مستقلة للأجسام كبيرة الحجم/المشوّهة والترميز غير الصحيح.
- إصلاح استيراد `deriveProductOverride` الناقص في مسار الإشراف، وإضافة `@types/node` اعتماداً مباشراً.
- تحسين طباعة 80mm وتاريخ إعداد التقرير/أسماء الملفات في منطقة البحرين، والإبقاء على حماية تصدير CSV من صيغ الخلايا التنفيذية.
- تحديث وثيقة الاستكمال `docs/CONTINUATION_FINDINGS.md` لتضم حالة الجولات ومصفوفة أولويات استمرار العمل.

## النتائج المنفذة (الجولة 4 — بيئة كاملة الاعتمادات)

- **إصلاح خلل جوهري قديم في الأقفال:** كانت أقفال المنتجات (`locks`) لا تعمل مطلقاً منذ الإصدار الأول — فحوص العضوية استخدمت عامل `in` على `Map` (13 موضعاً في `generate.ts`). أُصلحت بـ`.has()`، وحُميت الأقفال من كل مسارات التعديل (سلّم العجز خطوات 3-6، سقف الترفيهات، طابور الترقيات الجشعة، التحسين المحلي)، وأُضيف إنذار صريح «تعذّر تثبيت …» لكل قفل غير قابل للتنفيذ (معرف غير موجود/غير متوفر/محجوب/احتياجه غير مطلوب) بدل الإسقاط الصامت.
- إضافة 4 اختبارات انحدار: القفل ينفَّذ مرة واحدة بكميته، يصمد تحت ميزانية متعذرة مع إعلان العجز رقمياً، القفل غير القابل للتنفيذ يُعلن بسببه، وظرف must لا يتجاوز سقفه مع إعلان العجز عند التعذر.
- إغلاق أبواب الجودة المعطلة سابقاً: `tsc --noEmit` تحت `noUncheckedIndexedAccess` صفر أخطاء (إصلاح خطأين حقيقيين في سكربت ETL)، و`eslint` صفر مشاكل (ضبط نطاق قاعدة `require` لملفات `.cjs` الموثق في D-027).
- التحقق من القفل: `bun install --frozen-lockfile` ناجح (827 حزمة، رمز خروج 0).
- تحقق مصفوفة الثوابت على محرك حقيقي بالكتالوج الكامل: مجموع الأسطر == إجمالي المحرك == إجمالي التشخيص؛ الحتمية بايت-ببايت؛ العجز معلن رقمياً عند تجاوز الهدف المحمي.
- E2E عبر متصفح فعلي: رئيسية ← تحليل نص حر ← معالج 7 خطوات ← خطة 42 بنداً (113.959 من 120 د.ب) بتبويبات الأنماط الخمسة وسلّم التخفيضات الظاهر — صفر أخطاء Console/Page. وE2E عبر API: الأقفال تعمل عبر عقود Zod، والأجسام غير الصالحة تُرفض برسائل منظمة.

## أدلة التحقق (أحدث تشغيل — الجولة 4)

| الفحص | النتيجة | الدلالة |
|---|---|---|
| `bun run test` | **22 ناجحاً / 0 فاشل**، exit 0 | محرك + تسوية بنود + أقفال + أظرف + تراكب منتجات + قارئ JSON |
| `bunx tsc --noEmit` | **0 أخطاء**، exit 0 | تحت `strict` + `noUncheckedIndexedAccess` مع اعتمادات كاملة |

## قيود ومخاطر مفتوحة

1. `next build` الإنتاجي وGitHub Actions وDocker لم يشغَّلوا بعد؛ التحقق التشغيلي تم عبر dev server واختبارات Node والمتصفح.
2. لا توجد اختبارات API تكاملية على قاعدة بيانات مؤقتة (مشاركة/مساهمات/إدارة/تراجع/تزامن) — أولوية P0 التالية.
3. لا توجد لقطات أو PDF من طباعة فعلية تؤكد عدم قص النص العربي في A4/A5/Letter/80mm، ولا فحص axe للوصولية.
4. مفتاح الإدارة المشترك ليس RBAC؛ لا تنشر لوحة الإدارة للعامة بلا مصادقة وأدوار مناسبة، ويلزم فحص تحديد المعدل خلف وكيل عكسي موثوق.
5. لم يُحسم الترخيص القانوني لإعادة توزيع بيانات وأسعار كل متجر؛ انظر `DATA_LICENSE.md`.
6. دقة التصنيفات والاحتياجات على كامل الكتالوج تحتاج تدقيقاً دلالياً واسعاً (يوجد حاجز دلالي تحفظي في المحرك لأعلى الفئات خطورة، لكنه ليس بديلاً عن التدقيق).
7. ظرف must قد يصل لأقرب تشكيلة دون حدّه الأدنى بفوارق تفصيل الأسعار، مع ملاحظة صريحة معروضة — لا يُزعم بلوغ الحد إن لم يحدث.

## تشغيل الفحوص بعد استعادة المشروع

1. استخدم إصدار Bun متوافقاً مع `bun.lock` وشغّل `bun install --frozen-lockfile` (متحقق منه: ينجح).
2. شغّل `bun run test`, `bun run lint`, `bun run typecheck`, `bun run build` واحفظ النتائج برموز الخروج.
3. أكمل اختبارات API/Playwright/axe والطباعة قبل إعلان الجاهزية للإنتاج.

**الخلاصة:** الجولات 2-4 حسّنت الترابط والصحة الحسابية وحدود المدخلات، وأصلحت خلل الأقفال الجوهري، ورفعت الاختبارات القابلة للتشغيل إلى 22/22 مع typecheck وlint أخضرين تحت أشد إعدادات TypeScript، وlockfile متحققاً. لم يُثبت بعد بناء الإنتاج وDocker/CI والوصولية والطباعة الفعلية؛ الوثائق تميز بصراحة بين ما نُفّذ وما اختُبر وما بقي غير متحقق.
