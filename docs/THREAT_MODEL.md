# نموذج التهديد (THREAT_MODEL) — «خصص بقالتك»

**آخر تحديث:** 26 أكتوبر 2026 (بعد جولة التطوير 4) · **المنهج:** STRIDE على كل مكون.
هذا النموذج وثيقة حية: أي إضافة لمسار API أو ميزة تخدم بيانات حساسة تُحدِّث هذا الملف ومصفوفة `docs/API_SECURITY_MATRIX.md`.

## 1. الأصول وما يحيط بها

| الأصل | أين يقيم | الحساسية |
|---|---|---|
| بيانات الأسرة (أعمار، حساسيات، عادات، رضيع، تدخين) | متصفح المستخدم (localStorage) — لا تُرسل للخادم إلا عند توليد خطة أو نشر بموافقة | عالية — بيانات شخصية عائلية |
| بيانات الخطة المنشورة (payload مجرد الأسماء) | جدول `SharedPlan` في SQLite | متوسطة — أعمار وعادات دون هويات |
| مفتاح الإدارة `ADMIN_API_KEY` | متغير بيئة الخادم + sessionStorage في متصفح المشرف (للجلسة فقط) | عالية — صلاحيات كاملة |
| سجل التدقيق (قبل/بعد لكل تعديل) | جدول `AuditEntry` | متوسط — يحوي حالات منتجات لا أسرار |
| مساهمات المجتمع وأصواته | `Contribution`/`Vote` | منخفضة — بلا حسابات؛ الهوية هاش يومي |
| الكتالوج المفتوح (أسعار/متاجر) | `data/curated/catalog.json` + تراكبات SQLite | منخفضة — مفتوح للتنزيل، حقوقه في DATA_LICENSE.md |

## 2. حدود الثقة

- **الخادم يثق بالعميل فقط عبر العقود**: كل جسم طلب يمر بـZod وحد حجم قبل أي تحليل، ولا هوية مدّعاة من العميل تُستخدم للإسناد.
- **ترويسات الوكيل (`X-Forwarded-For`/`X-Real-IP`) لا تُصدَّق إلا عند `TRUST_PROXY_HEADERS=true`** — صحيح خلف وكيل يعيد كتابتها (Caddyfile المشروع)، وخاطئ خلف وكيل يضيف إليها.
- **بوابة الإدارة مفتاح مشترك**: صلاحية واحدة كاملة لمن يملك المفتاح. ليست RBAC ولا جلسة مستخدم. في الإنتاج بلا مفتاح: 503. في التطوير: Host يشير إلى loopback فقط — **ترويسة قابلة للانتحال؛ هذا تسهيل تطوير لا حد أمني**.
- **حدود المعدل داخل الذاكرة**: تحمي العملية الواحدة، وتُتجاوز نظرياً بإعادة تشغيل أو بتوزيع المصادر — موثقة كحد معماري.

## 3. STRIDE

### Spoofing (انتحال الهوية)

| التهديد | المتحقق منه | المخفّت | المتبقي |
|---|---|---|---|
| انتحال مشرف بإرسال مفتاح مسروق | — | ترويسة `x-admin-key` بمقارنة زمنية ثابتة؛ حماية تخمين 12 فشل/5 دقائق لكل IP → 429 | سرقة المفتاح نفسه تمنح صلاحية كاملة (طبيعة المفتاح المشترك) — الدوران الدوري مسؤولية النشر |
| انتحال هوية مصوّت عبر توليد voterKeys جديدة | قيد التفرد `(contributionId, voterKey)` | حد معدل 60/دقيقة لكل IP | بلا حسابات يمكن الإجماع المزيف بجهد كبير؛ يُعرض التصويت في الواجهة بوصفه استرشادياً منخفض الثقة |
| انتحال IP عبر ترويسات الوكيل | `TRUST_PROXY_HEADERS` معطل افتراضياً | التفعيل موثق بشرط وكيل يعيد الكتابة | تفعيله خلف وكيل يضيف (لا يستبدل) يفتح الانتحال — موثق في .env.example |
| انتحال loopback في التطوير عبر Host مزيف | فحص ترويسة Host | 403 لغير loopback | الترويسة نفسها قابلة للانتحال من عميل مباشر — لا يُعتد بالوضع غير المُهيأ كحد أمني |

### Tampering (التلاعب)

| التهديد | المخفّت | المتبقي |
|---|---|---|
| جسم طلب متلاعب به يفسد الكتالوج | عقود Zod صارمة عند كل مسار كتابة (إدارة/مساهمة/نشر/خطة)؛ `deriveProductOverride` يعيد اشتقاق الحقول المشتقة ولا يقبل سعراً غير صحيح | مراجعة بشرية للمساهمات قبل التطبيق (طابور moderate) |
| تحديث جزئي يفقد بيانات المتجر (url/origFils) | دمج البقع الجزئية مع الحفاظ على الحقول غير المعدلة | — |
| تطبيق نصف معاملة عند انقطاع منتصف استيراد | معاملات قاعدة بيانات ذرية للتعديل+التدقيق؛ dry-run قبل apply | اختبار انقطاع فعلي قيد المتابعة (P1) |
| تلاعب العميل بأرقام الخطة | الإجماليات تُحسب خادمياً من المحرك؛ الواجهات تستهلك `getAllPlanItems()` من مصدر واحد | — |

### Repudiation (إنكار)

| التهديد | المخفّت | المتبقي |
|---|---|---|
| إنكار تعديل إداري | `AuditEntry` يسجل الفاعل/الإجراء/قبل/بعد/الوقت والتراجع يعلّم `revertedAt` | الفاعل إما "admin" (مفتاح مشترك) أو هاش مجهول — لا إسناد فرد بلا RBAC |
| إنكار نشر خطة | `consentToPublishHousehold: z.literal(true)` إلزامية في العقد | — |

### Information Disclosure (إفشاء)

| التهديد | المخفّت | المتبقي |
|---|---|---|
| كشف خطة خاصة بمعرفة slug | `isPublic=false` → 404 دائماً (مُختبر آلياً) | — |
| تسريب أسماء أفراد الأسرة في النشر | تجريد الأسماء والمعرفات (`shared-member-N`) قبل التخزين (مُختبر آلياً) | البيانات المنشورة تبقى قابلة لإعادة التعريف نظرياً بمجموعة التفاصيل — يُفصح عن ذلك في موافقة النشر |
| تسريب ملاحظات المراجعة الداخلية | الطابور العام يعيد `pending` فقط دون `reviewNote/reviewedBy/submittedBy` (مُختبر) | — |
| stack traces/رسائل قاعدة بيانات للعميل | شكل خطأ موحد `{error}`؛ التفاصيل تُسجل خادمياً | — |
| كشف مفتاح الإدارة عبر API/سجلات | لا مسار يعيد قيمة المفتاح؛ التخزين العميلي sessionStorage للجلسة فقط | — |
| IP المساهم المخزّن خام | هاش SHA-256 بملح يومي | — |

### Denial of Service (حجب)

| التهديد | المخفّت | المتبقي |
|---|---|---|
| إغراق توليد الخطة (CPU) | 60/دقيقة لكل IP + `maxDuration` | توزيع المصادر على IPs متعددة يتجاوز الحد — يحتاج مخزناً مشتركاً عند التوسع |
| إغراق النشر/المساهمات | 6/دقيقة (ذاكرة) + 10/ساعة (قاعدة بيانات لكل هاش) | نفس الحد أعلاه |
| جسم ضخم قبل التحليل | عدّ البايتات المتدفقة + فحص Content-Length → 413 | — |
| تصدير الكتالوج الضخم في حلقة | 6/دقيقة | — |
| تخمين مفتاح الإدارة | 12 فشل/5 دقائق → 429 مع Retry-After | — |

### Elevation of Privilege (تصعيد الصلاحية)

| التهديد | المخفّت | المتبقي |
|---|---|---|
| مساهم عام يصبح "approved" بلا مراجعة | انتقال الحالة عبر مسار الإشراف المحمي فقط | — |
| حقول مجهولة تصل التراكيب وتؤثر بالمحرك | قائمة سماح للحقول القابلة للتحرير (ProductPatchSchema) | — |
| قراءة ملفات النظام عبر مسار استيراد | مصادر الاستيراد مقيدة بمجلد البيانات المعتمد مع فحص realpath | اختبار عبور مسار `..`/symlink ضمن P1 |

## 4. قرارات نشر موصى بها

1. اضبط `ADMIN_API_KEY` طويلاً عشوائياً في النشر العام، ودوّره دورياً؛ لا تنشر لوحة الإدارة أمام أكثر من مشرف بلا طبقة مصادقة/أدوار حقيقية.
2. شغّل التطبيق خلف وكيل يعيد كتابة ترويسات IP (مثل Caddyfile المشروع) وفعّل `TRUST_PROXY_HEADERS=true`.
3. امنح قاعدة SQLite نسخاً احتياطياً دورياً (تحتوي الخطط المنشورة والسجلات).
4. فعّل TLS عند الوكيل (المعاينة الحالية عبر المنفذ المكشوف).
5. راقب السجلات بحثاً عن 429 المتكرر (محاولات تخمين/إغراق) — لا تحوّلها إلى تنبيه يحوي هويات.
