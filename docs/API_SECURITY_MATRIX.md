# مصفوفة أمان واجهات API — «خصص بقالتك»

**آخر تحديث:** 26 أكتوبر 2026 (بعد جولة التطوير 4) · **إجمالي نقاط النهاية:** 18 مساراً في `src/app/api/**/route.ts`

هذه المصفوفة تغطي كل مسار فعلي في التطبيق: طريقة الطلب، التصنيف، المصادقة، حدود الجسم/الاستعلام، تحديد المعدل، حالات الفشل، البيانات الحساسة، واختبار القبول. أي تغيير في مسارات API يجب أن يحدّث هذا الملف.

## آليات مشتركة

| الآلية | الملف | الوصف |
|---|---|---|
| بوابة الإدارة | `src/lib/server/admin-auth.ts` | مفتاح مشترك `ADMIN_API_KEY` عبر ترويسة `x-admin-key` بمقارنة `timingSafeEqual`. ليست RBAC ولا جلسة مستخدم. فشل المطابقة يُحسب لكل IP: 12 محاولة فاشلة/5 دقائق → 429. غير مهيأ + `NODE_ENV=production` → 503. غير مهيأ في التطوير → مسموح فقط لترويسة Host تدل على loopback (403 لغيرها) — الترويسة قابلة للانتحال فهذا تسهيل تطوير لا حد أمني؛ الإنتاج يجب أن يضبط `ADMIN_API_KEY`. |
| قارئ جسم محدود | `src/lib/server/request-body.ts` | يرفض تجاوز الحجم قبل `JSON.parse` (فحص `Content-Length` ثم عدّ البايتات المتدفقة)، ويرفض UTF-8 غير الصالح وJSON التالف بأكواد مستقرة. |
| تحديد المعدل | `src/lib/server/rate-limit.ts` | عدّاد نافذة ثابتة داخل الذاكرة لكل عملية (`name:ip`). نطاقه العملية الواحدة — ليس حداً عالمياً بين نسخ متعددة (موثق في KNOWN_LIMITATIONS). IP العميل من `X-Forwarded-For`/`X-Real-IP` فقط عند `TRUST_PROXY_HEADERS=true` (صحيح خلف وكيل يعيد كتابة الترويسات كما في Caddyfile المشروع؛ بلا الوكيل تُقاس كل الطلبات بدلو واحد). الاستجابة 429 مع `Retry-After`. |
| شكل الخطأ الموحد | كل المسارات | `{ "error": "<code>" }` (وبعضها يضيف `issues[]` لتحقق Zod). لا تُرسل stack traces ولا رسائل قاعدة البيانات للعميل؛ التفاصيل تُسجل خادمياً بلا أسرار. |

## ملاحظات مخاطر متبقية (موثقة بأمانة)

1. **المفتاح المشترك ليس RBAC:** كل من يملك `ADMIN_API_KEY` يملك صلاحيات كاملة. النشر العام متعدد المشرفين يحتاج طبقة مصادقة/أدوار أمامية (انظر THREAT_MODEL). لا يُعرض المفتاح في أي استجابة API، ولا يُخزَّن في localStorage دائم — واجهة الإدارة تحفظه في `sessionStorage` فقط ويُرسل كترويسة، لا في URL.
2. **حدود الذاكرة لكل عملية:** `rate-limit.ts` يحمي النسخة الواحدة؛ التوسع الأفقي يحتاج مخزناً مشتركاً (مستقبل: Redis) — القرار D-029.
3. **تصويت بلا حساب:** `voterKey` من العميل قابل للتوليد بلا حدود؛ خفّضنا إمكانية الإساءة بحد المعدل لكل IP وبقيد التفرد `(contributionId, voterKey)` مع معالجة سباق الإدراج المتزامن (P2002). لا يزال الإجماع على التصويت ثقة منخفضة بحكم التصميم بلا حسابات — يعرض أثره في صياغة واجهة المجتمع («تصويت مجتمعي استرشادي»).
4. **الثقة بترويسات الوكيل:** معطلة افتراضياً؛ تُفعَّل خلف وكيل يعيد كتابة الترويسات (Caddyfile المشروع). التفعيل الخاطئ أمام وكيل يضيف (بدل أن يستبدل) يسمح بانتحال IP.
5. **لا CORS مخصص ولا cookies للجلسات:** المصادقة بترويسة لكل طلب، فلا توجد حالة جلسة قابلة لـCSRF؛ الطلبات كلها same-origin من الواجهة، والمسارات العامة للقراءة لا تحتاج CORS.
