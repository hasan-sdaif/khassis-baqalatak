# خوارزمية الاقتراح (ALGORITHM.md)

> المرجع التقني الكامل للمراحل التسع (المواصفة قسم 6) مع الاشتقاقات والأمثلة.

## 0. العقد العام

```ts
generatePlan(input: {
  catalog, household, budget, context, config,
  locks?, exclusions?, envelopes?, pantry?, seed
}): PlanResult
```

دوال نقية حتمية بلا I/O؛ نفس المدخلات ← نفس المخرجات (bit-for-bit). كل المبالغ فلس (int).

## 1. تقدير الطلب (demand.ts)

لكل احتياج `n` وفترة `H` يوماً:
```
D_n = Σ_m rate(n, class(m)) × (H/30) × λ_season × λ_household × λ_eating_out − pantry
```
- `rate`: قواعد استهلاك لكل فئة عمرية (بالغ-مكافئ: طفل 1–3 ≈ 0.4 … مراهق ≈ 1.0، مسن 0.85، حامل/مرضعة +0.15 لفئات محددة).
- **وحدات العادات** (رضّع/تبغ/قهوة/شاي/مياه/غازية) تضيف طلباً خاصاً:
  - الحفاضات: `changes/day(العمر) × H` لكل رضيع، **مقاس من وزن WHO الوسيط** (قرب الحد الأعلى ← يرجَّح الأكبر + تحذير انتقال) — معرف المتغير `diapers@size`.
  - حليب الأطفال: `ml/day(العمر) × 0.135 × نسبة الاعتماد × H` غراماً، **مرحلة من العمر** (`formula@stage`) + قفل العلامة + تحذير قرب الانتقال.
  - التبغ: بند ثابت (علامة + كمية مقفلة) يُحجز قبل كل شيء؛ سعر يدوي عند غياب البيانات.
- المطبوخ منزلياً يُخفض بـ`λ_eating_out = max(0.55, 1 − وجبات_خارج/42)`؛ الضيافة ترفع (قهوة/شاي/تمر/مياه) `λ = 1 + min(1.5, ضيوف/30 × 0.4)`.
- المواسم: رمضان (تمر ×3، عصائر ×1.8…)، العيد، العودة للمدارس، الصيف.

## 2. ترشيح المنتجات (buildCandidate)

استبعاد حازم: غير متوفر/بلا سعر، علامة/منتج محجوب، حساسيات (مكسرات بنص الاسم)، **مرحلة الحليب ومقاس الحفاضة**، أنواع الحليب الخاصة (لاكتوز/AR/HA…)، **عدم تطابق عائلة الوحدة** (منتج ملّي لا يلبّي احتياجاً وزنياً). التثبيتات تدخل كما هي.

## 3. ملاءمة العبوة والهدر (القلب الرياضي)

لكل منتج بحجم `q` وسعر عبوة `c` ومعدل يومي `r = D/H`:
- قابلية الاستهلاك للعبوة المفتوحة: `perPack = min(q, r·s_open)` (حليب طازج مفتوح 4 أيام…).
- **هدر الصلاحية المغلقة يُقيَّم لكل رحلة** (المواد الطازجة تُشترى أسبوعياً): `loss = max(0, (packsPerTrip−1)·q/r − s_sealed)·r·trips`.
- `usable = min(k·q, k·perPack − loss)`، `waste% = 1 − usable/(k·q)`، `coverage = usable/D`.
- اختيار `k` بدالة عقوبة: `k·c + 1.2·wasteValue + 2.5·shortfall·u_ref + 0.2·k`.
- **سعر الوحدة الفعّال** `u_eff = k·c / usable` — هو المرجع في المقارنات لا سعر الوحدة الظاهري.
- `fit = exp(−ω/τw)·exp(−|ln(k/k_comfort)|/τk)·(k > 6·k_comfort ? 0.4 : 1)` حيث `k_comfort` يتبع عدد الرحلات للمواد الأسبوعية.

**أمثلة محققة بالبيانات الحقيقية:**
- أسرة 7 أفراد: حليب طازج `r ≈ 0.88 لتر/يوم` ⇒ عبوة 6×200مل بلا هدر (`r·4 = 3.5L ≥ 1.2L`)؛ اختار المحرك **25 عبوة (30 لتراً) بـ 4.250 د.ب**.
- فرد واحد: نفس الاحتياج/فرد ⇒ عبوة 1 لتر (عبوة 6×200مل ستبقى 60% منها فاسدة بعد الفتح).
- دجاج كامل مجمد 900جم ×20 لأسرة (لاحظ المواصفة: الأساسيات قابلة للتخزين تقبل عبوات أكبر).

## 4. النقطة المثلى (Sweet Spot)

- توزيع `u_eff` الموزون بالانتشار (متاجر + رتبة) لكل احتياج ⇒ الرتبة المئيلية `π_i`.
- مؤشر السعة: `T = B_avail / B_ref` حيث `B_ref` كلفة خطة مرجعية بالوسيط.
- `π*_n = clamp(0.5 + A·tanh(κ·(T−1)) + δ_class + δ_user + δ_mode, π_min, π_max)`
- درجة الأنسب:
```
S = w_t·exp(−(π_i−π*)²/2σ²) + w_fit·fit + w_v·(1−π_i) + w_a·avail
  + w_p·popularity + w_b·brandTrust + w_f·pref − w_w·ω − w_c·(1−conf)
```
- حدود أمان: رفض > 2.5× وسيط (إلا بطلب) و < 0.35× وسيط بلا إجماع متاجر.

## 5. القوائم القصيرة (≤8): تمثيل ثلاث شرائح اقتصادي/متوسط/مميز + أفضل علامة مفضلة + إسقاط المهيمَن عليه (كلفة أعلى ودرجة وتغطية أقل).

## 6. التخصيص تحت الميزانية (Greedy MCKP)

- خيار أساس: أوفر خيار مقبول لكل احتياج؛ منفعة `U = W_class · g(S) · min(1.15, cov) · penalty(cov < 0.92 للأساسيات)` مع `g` مقعّرة.
- **طابور ترقيات**: منتجات أفضل + **زيادة كمية/تغطية** + مستويات الأظرف — يُطبَّق الأفضل عائداً حدياً `ΔU/Δcost` بشرط `≥ λ_min (2e-5/فلس)` فلا إنفاق لمجرد الإنفاق.
- سقف التحلية 8% من الميزانية (الأظرف `must` مستثناة).
- **سلّم تقليص العجز الشفاف** (عند تجاوز الأساس للميزانية): حذف الترفيهي ← الرفاهية ← **تبديل لعبوات ميسورة** (سعر وحدة ≤ 2× الوسيط + أقل كلفة كلية) ← تقليص كميات الاعتيادي ← الأساسيات (لا تقل عن عبوة) — **بنود الرضّع لا تُمسّ أبداً** — مع سجل كامل يُعرض للمستخدم مع رقم الفجوة.

## 6ب. حلّال الأظرف (spec 6.20)

لكل ظرف: مستويات إنفاق من `min` إلى `max` بخطوة 250 فلس؛ لكل مستوى **تشكيلة** تُبنى جشعاً بدالة شبه-مقعّرة:
```
U_env = Σ w_j·g(spend_j) + λ_v·Variety + λ_t·TargetFit + λ_a·AudienceFit − λ_w·Waste − λ_c·Overbuy
```
بقيود: سقف علامة واحدة، أعداد دنيا/قصوى، استبعاد الحساسيات/الأعمار، **سقف الاستهلاك المعقول** (يتوقف قبل `max` إن كفى: «ننصب 3.800 من 7.000 لأنها تغطي استهلاككم») إلا بتفعيل `fillToMax`. `min` محجوز حسب الأولوية (`must` كالثوابت) والفارق `[min,max]` ينافس كترقيات. كشف التداخل بين الأظرف + فجوة Σmins بشفافية.

## 7. تحسين المتاجر

أنماط: الوسيط (مرجع) / أرخص متجر واحد (استبدال غير المتوفر ببدائل نفس الاحتياج) / سلة موزعة (إسناد كل بند لأرخص متجر ثم دمج المتاجر الصغيرة إذا رجحت رسوم التوصيل، مع احترام الحد الأدنى). المخرجات: تكلفة كل نمط، التوفير مقابل الوسيط، قائمة لكل متجر، اقتراح «أضف X لتحصل على توصيل مجاني».

## 8. الفحوص (Invariants)

Σ cost ≤ B_target (إلا ثوابت إلزامية أعلى — تُعلَّم)؛ لا كميات سالبة/صفرية؛ لا منتجات محجوبة/مخالفة؛ لا مرحلة/مقاس خاطئ؛ تغطية الأساسيات تُعرض بأمانة.

## 9. الشرح والبدائل

لكل بند أكواد أسباب تُترجم لجمل عربية تحمل أرقام الاشتقاق («أسرتكم 7 أفراد وتستهلك ≈26 لتراً… اخترنا 25 عبوة 6×200مل بسعر 0.142 د.ب/لتر — أوفر من وسيط الفئة بـ17% وبلا هدر»). 3 بدائل: أوفر/مكافئ/أفضل بفروق الكلفة وملاحظات. تشخيص الخطة: توزيع بالفئات، متوسط π، الهدر، التنويع، الثقة، تحذيرات، وبصمة (hash + إصدارات).

## المعايرة الحية

## 11. المرحلة 6.5 الجديدة — التحسين المحلي (Hill-Climbing)

بعد التوزيع الطماعي وسقف التحلية، تجري ≤3 جولات تحسين محلي حتمية (ترتيب: حجم الطلب تنازليًا):
- **تبديلات**: لكل احتياج، نبحث في قائمته المختصرة عن بديل ذي منفعة أعلى (منفعة الفئة × مُعوّل التوزيع) دون تجاوز الهدف.
- **تقليص الكمية**: عبوة أقل إذا بقيت المنفعة (إزالة هدر).
- تُرصد الجولات والمكاسب في `diagnostics.refinementPasses/refinementGains` وتُعرض للمستخدم («حسّنا الخطة بـN جولات تبديل ذكية»).

## 12. فرض التوزيع بالنسب (قيد مرن)

عند تفعيل `allocation.enforce` يصبح مُعوّل منفعة كل احتياج:
```
allocW = clamp(1 + (target% − achieved%)/100 × 1.2, 0.6, 1.7)
```
فيدفع الترقيات الطماعية والتحسين المحلي الإنفاق نحو نسب المستخدم. لوحة «شفافية الخطة بالأرقام» تعرض المستهدف مقابل المحقق لكل مجموعة مع أشرطة مزدوجة وحبة فرق (أخضر ≤3% وإلا عنبري).

## 13. الشفافية المئوية (توجيه «حدّد النسب المئوية»)

- **تركيبة التقييم لكل بند** (`scoreParts`): الملاءمة السعرية/جودة العبوة/القيمة السعرية/العلامة والتفضيل/التوفر والشهرة + خصم الهدر والثقة — نِسَب من مجموع المقادير، تُعرض أشرطة في نافذة «لماذا؟».
- **إزاحة الوضع** معروضة كنسبة صريحة على كل تبويب: طوارئ −32% / اقتصاد −18% / توازن 0% / راحة +15% / مخصص (−35..+25 منزلق حي).
- **بطاقات المقارنة** تحسب فرق النسبة بين الأنماط («أوفر بـX% من المتوازن»).
- **شفافية المعالج**: مكافئون بالغون، أثر الأكل الخارجي ≈X%، أثر الضيافة ≈Y%، احتياطي المرونة N%، حصة الترفيه.

## 14. اقتصاد السعرات (من ملف الإلهام §3.3)

تُقدَّر السعرات من جدول كثافة الطاقة لـ26 أساسًا (أرز 3.6 kcal/جم، زيت 8.84/مل، بيضة 78…) مقسومة على المكافئين البالغين والأيام: `approxCaloriesPerDay` + `costPer1000kcalFils` (كلفة كل 1000 سعرة) — تُعرض بجانب مجموعات التغذية مع إخلاء مسؤولية صريح.

## 15. سُلَّم الميزانية والمقترح الذكي (من ملفات الإلهام 00/01/09)

```

economy:    40 + 11 × (المكافئون − 1)     ← مرساة العازب بالـ40 من توجيه المستخدم

```

## 16. حتمية المحرك محفوظة

أُعيد تشغيل السيرة السلوكية (7 سيناريوهات الأصلية) قبل وبعد الترقية على نفس الكتالوج: نتائج **متطابقة بايت-بايت** في غياب الملف المتقدم — الترقية إضافية صرفة لا تغير السلوك الافتراضي. سيناريوهات متقدمة جديدة: نباتي+بلا كافيين+حلاوة 40%، كيتو+قيمة 60%+حليب ثابت 6 لتر، طوارئ+بروتين 40% مفروض+احتياطي 10%.
