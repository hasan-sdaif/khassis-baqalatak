# قائمة تحقق ما قبل الإصدار (RELEASE_CHECKLIST)

قائمة خطية تُنفَّذ بالترتيب قبل أي إصدار (وسم جديد). لا تُعلّن النتيجة إلا بما تحقق فعلاً في التشغيل — قاعدة الحالة موثقة في `PROGRESS.md`. انسخ هذه القائمة إلى وصف الإصدار وعلّم البنود المنجزة مع الأدلة (أرقام، سطور أوامر، لقطات).

## القائمة

- [ ] **1. تثبيت نظيف من الـ lockfile في مستودع نظيف**
  انسخ المستودع (أو `git clone` نظيف) إلى مجلد جديد ونفّذ `bun install --frozen-lockfile` — ينجح بلا تغيير على `bun.lock`. تحذير معروف: متغير `DATABASE_URL` المُصدَّر في الجلسة يتفوق على `.env` لدى Prisma؛ تحقق من نتيجة نظيفة بقشرة بلا متغيرات ملوثة (مثل `env -u DATABASE_URL ...`) حتى لا تختبر قاعدة ببيانات قديمة بالخطأ.

- [ ] **2. `prisma db push` على قاعدة فارغة**
  `cp .env.example .env` ثم `bunx prisma db push` على قاعدة SQLite غير موجودة — يُنشئ المخطط كاملاً بلا أخطاء، وينشئ `/api/health` استجابة `{"status":"ok","db":true,"catalogFile":true}`.

- [ ] **3. الفحوص الأساسية خضراء**
  `bun run test` (المحرك، 22/22)، `bun run typecheck` (`tsc --noEmit` تحت `strict` و`noUncheckedIndexedAccess` — صفر أخطاء)، `bun run lint` (صفر مشاكل). سجّل الأرقام الفعلية في ملاحظات الإصدار.

- [ ] **4. خادم حي + اختبارات API**
  شغّل `bun run dev` (أو خادم الإنتاج) ثم `bun run test:api` — النتيجة المطلوبة **11/11**. بدون خادم حي تُتخطى الحزمة بشفافية؛ هذا البند لا يُعلَّم إلا بتشغيل فعلي مقابل خادم.

- [ ] **5. تدقيق UX أساسي على 360/1440**
  افتح التطبيق على عرض 360px ثم 1440px (يفضل إضافة 768px): لا فائض أفقي (`scrollWidth <= clientWidth + 1`) في الرئيسية والكتالوج والخطة، الوضع الداكن يعمل، تبديل EN/AR يضبط `dir`/`lang`. راجع `docs/UX_AUDIT.md` لمعيار التدقيق.

- [ ] **6. طباعة A4/A5/Letter/80mm عبر `preferCSSPageSize`**
  صدّر تقريراً بكل مقاس من الأربعة وتحقق من مقاس الصفحة الفعلي (MediaBox عبر `pdfinfo` أو أداة تدقيق تستخدم `preferCSSPageSize` — بدونها تعرض أدوات PDF القياسية Letter للجميع). تذكر: 80mm يستخدم `@page size:auto` عمداً (رول الطابعة يحدد العرض — القرار D-025)، فتحقّق من عرض المحتوى (74 مم) وعدم وجود فائض أفقي في المعاينة.

- [ ] **7. فحص الأسرار في الملفات المتتبعة**
  `rg -n "ghp_|sk-|AKIA|API_KEY" -- $(git ls-files)` (أو ما يكافئها) على الملفات المتتبعة كاملة — صفر نتائج حقيقية. تحقق أيضاً: لا `.env` ولا `*.db` ولا `node_modules` في `git ls-files`. أي سر عُرّض عرضاً يُدوَّر فوراً قبل الإصدار.

- [ ] **8. تحديث وثائق الحالة**
  `CHANGELOG.md` (بنود هذا الإصدار بتواريخ وأرقام حقيقية)، `PROGRESS.md` (ما تحقق فعلاً في التشغيل)، `docs/KNOWN_LIMITATIONS.md` (كل حد جديد أو حد أُغلق — بالحذف أو التعديل لا بالتجاهل).

- [ ] **9. توثيق القرارات الجديدة**
  كل قرار تصميمي اتُّخذ أثناء الدورة مسجّل في `docs/DECISIONS.md` بترقيم متسلسل (`D-0XX`) مع البدائل المرفوضة والسبب. القرارات غير الموثقة تُعدّ ديناً على الإصدار.

- [ ] **10. الوسم وملاحظات الإصدار**
  حدّث `version` في `package.json` بما يطابق الوسم، ثم `git tag vX.Y.Z` وRelease Notes على GitHub تلخص: ما الجديد (من CHANGELOG)، نتائج البنود 1–7 بالأرقام، والحدود المعروفة المتبقية (رابط KNOWN_LIMITATIONS).

## ملاحظة

هذه القائمة دنيا وليست سقفاً: أي إضافة معمارية (مصادقة، مخزن معدل مشترك، CI) تستوجب بنوداً جديدة هنا قبل أول إصدار يعتمدها.
